# AFTER FIX — Forged token WITH type=user, signed with the OLD secret (BLOCKED)

# Goal:
#   Try to defeat the type check by including type: "user" in the forged
#   payload, but still sign it with the recovered placeholder secret.

# Command:
curl.exe -i http://localhost:5000/api/users/profile -H "Authorization: Bearer $FORGED_WITH_TYPE"

# Output:
HTTP/1.1 401 Unauthorized

Connection: keep-alive
Keep-Alive: timeout=5

{"message":"Invalid or expired token"}

# Description:
Even with a correct-looking type claim, the token still fails because
the JWT secret was rotated in the previous fix. Signing with the old
secret now produces an invalid HMAC, so jwt.verify throws before the
type check even runs. This is the second layer of defence: rotating
the secret blocks re-use of any old forgery, and the type check blocks
cross-role abuse with a valid signature.
