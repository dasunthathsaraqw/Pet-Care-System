1. VULNERABILITY FINDINGS & RISKS
-------------------------------------------------------------------------------
Finding 5.1: Weak and Predictable JWT Secret Key (CWE-321)
- Location: backend/.env
- Risk: The application previously used a hardcoded default string ("your_jwt_secret_key").
  An attacker could forge valid JWT signatures for any account ID.

Finding 5.2: Missing Token Type Enforcement / Cross-Role Token Reuse
- Locations: All auth controllers and authentication middlewares
- Risk: A single JWT_SECRET was shared across user, admin, and professional authentications
  without checking the target role type in the token payload. A token issued for a regular
  user could be accepted by admin or professional routes.

2. REMEDIATION STEPS COMPLETED
-------------------------------------------------------------------------------
--- ATTACK 1 FIX: JWT Secret Hardening ---
Step 1: Cryptographically Strong Secret Generation
- Generated a 256-bit (32-byte) pseudo-random hex key via Node.js crypto:
  Value: 4b356c072a5a93b36a322797bf2ad6d574ec9df2b6cc36b9b0a50e05860b158a

Step 2: Environment Configuration Update
- Replaced the weak secret in `backend/.env` with the generated 64-character hex key.

Step 3: Version Control Protection
- Added `.env` to `backend/.gitignore` and executed `git rm --cached backend/.env` to 
  untrack sensitive configuration files from git tracking.

--- ATTACK 2 FIX: Token Type Claim & Enforcement ---
Step 4: Added Explicit `type` Claim to Token Payloads
- Updated all token issuance routines to include an explicit `type` claim:
  * `backend/controllers/userController.js`: Added `type: "user"` to `generateToken` and `updateProfile`.
  * `backend/controllers/adminController.js`: Added `type: "admin"` to `login`.
  * `backend/controllers/profController.js`: Added `type: "professional"` to `profLogin` and `generateToken`.
  * `backend/controllers/googleAuthController.js`: Added `type: "user"` to `createApplicationToken`.

Step 5: Enforced Token Type Verification in Middlewares
- Updated all authentication middlewares to verify that `decoded.type` matches expected type,
  rejecting invalid role tokens with generic 401 ("Invalid or expired token"):
  * `backend/middleware/authMiddleware.js`: Requires `decoded.type === "user"`.
  * `backend/middleware/auth.js`: Requires `decoded.type === "user"`.
  * `backend/middleware/adminAuthMiddleware.js`: Requires `decoded.type === "admin"`.
  * `backend/middleware/profMiddleware.js`: Requires `decoded.type === "professional"`.
  * `backend/middleware/professionalAuth.js`: Requires `decoded.type === "professional"`.
  * `backend/middleware/authProfessionalforcreate.js`: Requires `decoded.type === "professional"`.

3. VERIFICATION & COMPLIANCE
-------------------------------------------------------------------------------
- Weak secret replaced with cryptographically secure 256-bit key.
- `.env` safely untracked and added to `.gitignore`.
- Cross-role token reuse prevented by explicit `type` claim check across all 6 auth middlewares.
- Non-auth tokens (e.g. OIDC transaction tokens) remain properly separated.
